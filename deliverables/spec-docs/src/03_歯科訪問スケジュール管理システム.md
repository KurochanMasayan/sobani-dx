## はじめに

### 本書の目的
本書は、そばにの訪問歯科診療業務で使用している **歯科訪問スケジュール管理システム** の概要仕様を、社内（内製）での運用・保守へ引き継ぐことを目的としてまとめたものである。何を管理するシステムか・どんなデータで構成されるか・居宅療養管理指導の算定をどう管理するかを、開発の専門家でなくても把握できる粒度で記述する。

### 対象読者
そばにで本システムの運用・保守を担当する方。Google スプレッドシートと AppSheet アプリの基本操作ができることを前提とする。

### 本書の位置づけ
> 本書は概要仕様書である。AppSheet アプリの画面・数式・オートメーションの細部は、**稼働中の実機（アプリ本体）が最終的な正となる**。本書と実機に差異がある場合は実機を優先すること。

---

## システム概要

本システムは、訪問歯科診療のスケジュール管理と、居宅療養管理指導の **算定管理** を統合する AppSheet アプリケーションである。

歯科は治療内容により訪問回数が大きく変動し（入れ歯作成時は毎週、破損対応で連続訪問など）、予定変更が頻繁に発生する。従来、診療スケジュールとタイムスケジュールを別々に管理して二重入力が生じていた課題を解消し、患者マスタの基本スケジュールから **月次スケジュールを自動生成** する。あわせて、歯科医師・歯科衛生士それぞれの算定上限を確実に守るための管理機能を備える。

## システム構成

本システムは Google のサービス上で完結する。AppSheet がアプリ画面と業務ロジックを担い、データは Google スプレッドシートに保持する。

```
   [ AppSheet アプリ ]              [ Google スプレッドシート ]
   画面・自動生成・算定チェック  ◀──▶   マスタ6表 / トランザクション系の表
   ・タイムスケジュールPDF生成
```

| 構成要素 | 役割 |
| --- | --- |
| AppSheet | 画面・フォーム・アクション・算定ロジック・訪問日計算・PDF 生成。 |
| スプレッドシート | 全データ（マスタ・トランザクション）の保管。 |
| GAS | レセプト出力連携などの将来拡張用（現時点では中心的役割を持たない）。 |

## データモデル

データは「マスタ系」と「トランザクション系」に大別される。以下は概念レベルの一覧である。

### マスタ系
| テーブル | 管理する内容 |
| --- | --- |
| 施設マスタ | 訪問先施設の名称・住所・連絡先・管理者。 |
| 患者マスタ | 患者属性（保険・負担割合・要介護度）、基本スケジュール（週・曜日・時間）、ステータス。 |
| 居宅介護支援事業所マスタ | ケアマネジャー側の事業所情報。 |
| スタッフマスタ | 歯科医師・歯科衛生士の氏名・役職・稼働曜日。 |

### トランザクション系
| テーブル | 記録する内容 |
| --- | --- |
| 診療スケジュール | 訪問日・時間・患者・施設・担当者・ステータス・医師／衛生士の算定フラグ・衛生士滞在時間・メモ。 |
| 患者不在時間 | 患者が定期的に不在となる曜日・時間帯（タイムスケジュール PDF に表示）。 |
| 日別訪問計画 | 特定日のスケジュールをまとめたもの。タイムスケジュール PDF の起点。 |
| スケジュール生成ログ | 月次自動生成の起点（対象年月を指定して生成を実行する）。 |

## 主要な処理・ルール

### 居宅療養管理指導の算定ルール
本システムの中核は、算定上限の超過を防ぐことにある。

| 区分 | 上限 | 要件 |
| --- | --- | --- |
| 歯科医師 | 同一患者につき **月 2 回** まで | 月の訪問回数が上限を超えても、算定できるのは 2 回まで。どの訪問で算定するかを選択・管理する。 |
| 歯科衛生士 | 同一患者につき **月 4 回** まで | 1 回あたり **20 分以上** の滞在が必須。20 分未満の訪問は算定不可。 |

- 算定回数の判定では、キャンセル済みの訪問はカウントしない。
- 算定の有無はアクション（ボタン操作）を通じて管理し、上限を超えないよう制御する。

### 月次スケジュールの自動生成
1. 「スケジュール生成ログ」に対象年月を指定して生成を実行する。
2. 患者マスタの基本スケジュール（訪問する週・曜日・時間）から、当月の具体的な訪問日を計算する。
3. 同一患者・同一日の重複が生じないようチェックしたうえで、診療スケジュールにレコードを追加する。
4. ステータスが「終了」の患者は生成対象から自動的に除外される。

生成後も、手動での編集・追加は継続して行える。

> 月次自動生成は、患者マスタに基本スケジュール（週・曜日・時間）が設定済みであることを前提とする。

## 帳票・PDF 出力

日別訪問計画をもとに、**タイムスケジュール PDF** を生成する。A4 横向きで、午前・午後に分けた一覧として、施設名・患者名・要介護度・時間・患者不在時間・備考などを表示する。生成された PDF はドライブの所定フォルダに保存される。

> PDF はテンプレート（Google ドキュメント）の行複製機能に依存する。レイアウトの崩れがある場合は簡易レイアウトに切り替える設計だが、実際の見え方は実機での確認が必要。

## 運用前提・制約

- 歯科用デジタルレセコンがクラウド非対応のため、データは Google スプレッドシート上で保持する。
- 月次自動生成は、同月の重複生成を防ぐためのチェックを前提とする。
- 患者不在時間は曜日・時間帯のパターンとして登録し、タイムスケジュール PDF に反映される。
- 利用には Google アカウントでの認証が必要。

> 仮想列（自動計算列）の再計算タイミング、PDF テンプレートの描画、曜日判定など、AppSheet 固有の挙動は実機により差が出る場合がある。運用前に実機で確認すること。

## 修正のしかた（メンテナンス）

このツールは **AppSheet の編集画面**で直す。プログラムのビルドは不要である。

1. AppSheet でこのアプリを開き、編集モードに入る。
2. 画面（ビュー）・列・アクション・自動化（Bot）などを、編集画面のメニューから変更する。算定ルールやスケジュール自動生成の条件も、AppSheet 上の設定（数式・アクション・Bot）で調整する。
3. 保存すると、利用者のアプリに反映される。
4. データの土台は Google スプレッドシートなので、項目の追加などはスプレッドシート側とあわせて確認する。

> AppSheet は設定を変えると即座に反映される。大きな変更の前に、現在の設定を控える／コピーアプリで試すと安心。
