## はじめに

### 本書の目的
本書は、そばにの訪問診療業務で使用している **医材在庫管理システム** の概要仕様を、社内（内製）での運用・保守へ引き継ぐことを目的としてまとめたものである。何を管理するシステムか・どんなデータで構成されるか・在庫がどう増減するかを、開発の専門家でなくても把握できる粒度で記述する。

### 対象読者
そばにで本システムの運用・保守を担当する方。Google スプレッドシートと AppSheet アプリの基本操作ができることを前提とする。

### 本書の位置づけ
> 本書は概要仕様書である。AppSheet アプリの画面・数式・オートメーションの細部は、**稼働中の実機（アプリ本体）が最終的な正となる**。本書と実機に差異がある場合は実機を優先すること。

---

## システム概要

本システムは、訪問診療で使用する医材（医療機器・医療材料）の在庫を管理する AppSheet アプリケーションである。最大の特徴は **箱単位での仕入れ・保管と、個数単位での患者への配布を二重に管理する** 点にある。

施設・患者ごとの定期配布（テンプレート化）と臨時配布に対応し、配布や入荷に応じて在庫が自動で増減する。定数在庫を下回った医材の発注判断を支援し、適切な在庫水準を保つことをねらいとする。偶数月・奇数月で配布数量を切り替える運用にも対応する。

## システム構成

本システムは Google のサービス上で完結する。AppSheet がアプリ画面と業務ロジックを担い、データは Google スプレッドシートに保持する。CSV 出力など一部の処理は Google Apps Script（GAS）が担う。

```
   [ AppSheet アプリ ]          [ Google スプレッドシート ]        [ GAS ]
   画面・入力・在庫計算  ◀──▶   マスタ / トランザクション各表  ──▶  CSV 出力
   （モバイル・タブレット対応）
```

| 構成要素 | 役割 |
| --- | --- |
| AppSheet | 画面・フォーム・アクション・在庫の自動計算・オートメーション。 |
| スプレッドシート | 全データ（マスタ・トランザクション）の保管。 |
| GAS | CSV 出力・データエクスポート等の補助処理。 |

## データモデル

データは「マスタ系（基本情報）」と「トランザクション系（日々の記録）」に大別される。以下は概念レベルの一覧である。

### マスタ系
| テーブル | 管理する内容 |
| --- | --- |
| 施設マスタ | 施設名・施設タイプ（施設／在宅／個人宅）・配布スケジュール等。 |
| 患者マスタ | 患者名・所属施設・有効フラグ。 |
| 商品マスタ | 商品コード・商品名・箱入数・単位・発注先・定数在庫・現在在庫・発注中数量。 |
| 発注先マスタ | 発注先の情報。 |
| 配布テンプレート | 患者×医材の定期配布数量（偶数月・奇数月の両方を保持）。 |
| セットテンプレートマスタ／構成明細 | 臨時配布用セットと、その中身（複数商品と個数）。 |

### トランザクション系
| テーブル | 記録する内容 |
| --- | --- |
| 箱詰記録 | 箱詰めした商品・施設・患者・数量（個数）・日付・作業者。 |
| 配布記録 | 実際の配布（施設・患者・商品・数量・日付）。 |
| 臨時配布記録 | セットテンプレートを用いた臨時配布の実績。 |
| 発注記録 | 発注した商品・箱数・単価・発注先・ステータス。 |
| 入荷記録 | 発注に対する入荷（箱数・日付・検品者）。分割入荷に対応。 |
| 在庫変動履歴 | 在庫の増減すべて（入荷・配布・調整・廃棄）を記録。在庫数量の根拠。 |

## 主要な処理・ルール

### 箱と個数の換算
在庫は商品マスタ上、**個数単位で一元管理**する。箱表示は箱入数から自動換算する（箱数＝個数÷箱入数、端数＝余り）。仕入れ・発注は箱単位、配布は個数単位という実務に合わせている。

### 在庫の自動増減
入荷・箱詰・配布といった記録が登録されると、在庫変動履歴に増減が記録され、商品マスタの現在在庫に反映される。在庫数量は在庫変動履歴の積み上げを根拠とする。

### 定数在庫と発注判断
商品ごとに定数在庫（適正な最低在庫）を設定できる。現在在庫＋発注中が定数を下回ると発注対象として識別され、不足分を箱単位に切り上げた発注数量の目安が示される。

### 偶数月・奇数月テンプレート
配布テンプレートは偶数月用・奇数月用の数量を持ち、当月が偶数月か奇数月かに応じて適用される数量が切り替わる。

### 発注から入荷までの流れ
発注記録を作成するとステータスは「発注済み」。入荷記録を登録すると入荷数量に応じて「一部入荷」→「入荷済み」へ進む。入荷記録は発注に紐づき、複数回に分けた入荷（分割入荷）にも対応する。

## 運用前提・制約

- 訪問先での利用を想定し、モバイル・タブレットに対応する（オフライン運用は要件外）。
- 利用には Google アカウントでの認証が必要。
- 在庫変動履歴は運用とともに件数が増加する（設計上想定済み）。大量データの CSV 出力時は分割実行を推奨。
- 自動発注の実行可否、棚卸（調整）の承認など、最終判断は管理者の操作を前提とする。

> 在庫不足時のバリデーションや、自動発注の「判定」から「発注記録への登録」までの自動化の範囲は、実機の設定により異なる場合がある。運用前に実機で挙動を確認すること。

## 修正のしかた（メンテナンス）

このツールは **AppSheet の編集画面**で直す。プログラムのビルドは不要である。

1. AppSheet でこのアプリを開き、編集モードに入る。
2. 画面（ビュー）・列・アクション・自動化（Bot／オートメーション）などを、編集画面のメニューから変更する。
3. 保存すると、利用者のアプリに反映される。
4. データの土台は Google スプレッドシートなので、項目の追加などはスプレッドシート側とあわせて確認する。
5. CSV 出力など一部の処理は GAS で動く。その部分を直す場合は、スプレッドシートの「拡張機能 → Apps Script」でコピー&ペーストで修正する（clasp 等は不要）。

> AppSheet は設定を変えると即座に反映される。大きな変更の前に、現在の設定を控える／コピーアプリで試すと安心。
