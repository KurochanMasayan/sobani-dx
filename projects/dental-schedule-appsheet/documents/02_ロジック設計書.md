## 1. 業務フロー分析

### 1.1 月次業務フロー

```
┌─────────────────────────────────────────────────────────────────┐
│                        月初                                      │
├─────────────────────────────────────────────────────────────────┤
│  1. 前月スケジュールを参考に当月スケジュール案を作成              │
│  2. 患者マスタの「訪問頻度」「曜日」を参考にベース日程を設定      │
│  3. 治療の進行状況に応じてイレギュラー調整                        │
└─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│                        日々の運用                                │
├─────────────────────────────────────────────────────────────────┤
│  1. 当日のスケジュールを確認                                     │
│  2. 医師/衛生士が訪問、診療実施                                  │
│  3. 帰院後、診療記録を更新                                       │
│  4. 算定フラグを設定（どの訪問で算定するか決定）                  │
└─────────────────────────────────────────────────────────────────┘
                                │

┌─────────────────────────────────────────────────────────────────┐
│                        月末                                      │
├─────────────────────────────────────────────────────────────────┤
│  1. 算定状況の確認（上限まで算定できているか）                    │
│  2. 算定漏れがあれば、残りの訪問で算定フラグを設定                │
│  3. レセプト（請求）作成用のデータ出力                            │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 訪問と算定の関係

**重要な概念：「訪問」と「算定」は別物**

```
例：患者Aさんへの月間訪問

  訪問1回目 (1/5)   → 医師算定 ○
  訪問2回目 (1/12)  → 医師算定 ○、衛生士算定 ○（25分滞在）
  訪問3回目 (1/19)  → 算定なし（医師は上限到達）、衛生士算定 ○（30分滞在）
  訪問4回目 (1/26)  → 衛生士算定 ○（20分滞在）
  訪問5回目 (1/30)  → 算定なし（緊急対応、治療のみ）

  結果：訪問5回、医師算定2回、衛生士算定3回
```

## 2. 算定ルール詳細

### 2.1 居宅療養管理指導とは

介護保険サービスの一つ。医師、歯科医師、薬剤師、歯科衛生士などが患者の居宅を訪問し、療養上の管理・指導を行うサービス。

### 2.2 歯科医師の算定ルール

| 項目 | 内容 |
|------|------|
| 算定上限 | **月2回まで**（同一患者に対して） |
| 条件 | 訪問診療を実施すること |
| 単位数 | 単一建物居住者の人数により異なる（下表参照） |

**単位数（令和6年6月改定後）：**

| 単一建物居住者数 | 単位数 |
|----------------|--------|
| 1人 | 517単位 |
| 2〜9人 | 487単位 |
| 10人以上 | 441単位 |

**算定判定ロジック：**
```
IF 当月の医師算定回数 < 2 THEN
    算定可能
ELSE
    算定不可（上限到達）
```

### 2.3 歯科衛生士の算定ルール

| 項目 | 内容 |
|------|------|
| 算定上限 | **月4回まで**（同一患者に対して） |
| 条件① | 1回あたり**20分以上**の実地指導（1対1） |
| 条件② | 歯科医師の指示に基づく実地指導 |
| 条件③ | 歯科医師と衛生士が共同で管理指導計画を作成 |
| 単位数 | 単一建物居住者の人数により異なる（下表参照） |

**単位数（令和6年6月改定後）：**

| 単一建物居住者数 | 単位数 |
|----------------|--------|
| 1人 | 362単位 |
| 2〜9人 | 326単位 |
| 10人以上 | 295単位 |

**20分要件の補足：**
- 20分未満の場合は算定不可
- 指導のための準備や利用者の移動に要した時間は含まない
- 開始・終了時刻を実施記録に記載する必要がある

**算定判定ロジック：**
```
IF 当月の衛生士算定回数 < 4 AND 滞在時間 >= 20分 THEN
    算定可能
ELSE IF 当月の衛生士算定回数 >= 4 THEN
    算定不可（上限到達）
ELSE IF 滞在時間 < 20分 THEN
    算定不可（20分未満）
```

### 2.4 衛生士の二軸管理

**課題：** 衛生士が20分以上滞在するためには、スケジュール上の制約がある

```
【例：衛生士Aの1日のスケジュール】

09:00 施設X 患者1（20分）→ 09:20終了
09:20 施設X 患者2（20分）→ 09:40終了  ※同じ施設なので連続可能
09:40 移動（30分）
10:10 施設Y 患者3（20分）→ 10:30終了
10:30 移動（45分）
11:15 施設Z 患者4（20分）→ 11:35終了

→ 4患者を診るのに2時間35分必要
→ 移動時間により、物理的に20分確保できない場合がある
```

**二軸の意味：**
1. **衛生士軸**：衛生士の移動・滞在スケジュール
2. **患者軸**：患者ごとの訪問予定・算定状況

## 4. 計算ロジック（Virtual Columns）

### 4.1 患者マスタに追加する仮想列

※ 以下の式では `USERSETTINGS("対象年月")` を使用する。
ユーザーがアプリ設定で対象月を切り替えることで、前月の算定確認や月初の精算作業にも対応できる。

```
【当月訪問回数】
COUNT(
  SELECT(診療スケジュール[スケジュールID],
    AND(
      [患者ID] = [_THISROW].[ID],
      MONTH([訪問日]) = MONTH(USERSETTINGS("対象年月")),
      YEAR([訪問日]) = YEAR(USERSETTINGS("対象年月")),
      [ステータス] <> "キャンセル"
    )
  )
)

【当月医師算定回数】
COUNT(
  SELECT(診療スケジュール[スケジュールID],
    AND(
      [患者ID] = [_THISROW].[ID],
      [医師算定] = TRUE,
      MONTH([訪問日]) = MONTH(USERSETTINGS("対象年月")),
      YEAR([訪問日]) = YEAR(USERSETTINGS("対象年月")),
      [ステータス] <> "キャンセル"
    )
  )
)

【当月衛生士算定回数】
COUNT(
  SELECT(診療スケジュール[スケジュールID],
    AND(
      [患者ID] = [_THISROW].[ID],
      [衛生士算定] = TRUE,
      MONTH([訪問日]) = MONTH(USERSETTINGS("対象年月")),
      YEAR([訪問日]) = YEAR(USERSETTINGS("対象年月")),
      [ステータス] <> "キャンセル"
    )
  )
)

【医師算定残り】
MAX(0, 2 - [当月医師算定回数])

【衛生士算定残り】
MAX(0, 4 - [当月衛生士算定回数])

【算定ステータス】
IF(
  AND([医師算定残り] = 0, [衛生士算定残り] = 0),
  "算定完了",
  CONCATENATE(
    IF([医師算定残り] > 0, "医師残" & [医師算定残り] & "回 ", ""),
    IF([衛生士算定残り] > 0, "衛生士残" & [衛生士算定残り] & "回", "")
  )
)
```

### 4.2 診療スケジュールに追加する仮想列

```
【施設名】（患者から自動取得）
LOOKUP([患者ID], 患者マスタ, ID, 施設ID)
→ さらに施設マスタから施設名を取得

【医師算定可能】
AND(
  [担当医師ID] <> "",
  LOOKUP([患者ID], 患者マスタ, ID, 医師算定残り) > 0
)

【衛生士算定可能】
AND(
  [担当衛生士ID] <> "",
  LOOKUP([患者ID], 患者マスタ, ID, 衛生士算定残り) > 0,
  OR([衛生士滞在時間] >= 20, ISBLANK([衛生士滞在時間]))
)

【20分警告】
IF(
  AND([担当衛生士ID] <> "", [衛生士滞在時間] < 20, [衛生士滞在時間] > 0),
  "⚠️ 20分未満",
  ""
)
```

## 6. 算定制限の実装方針

### 6.1 3層防御アプローチ

算定上限を確実に守るため、AppSheetネイティブ機能のみで3層の防御を実装する。

```
┌─────────────────────────────────────────────────────────┐
│  Layer 1: UI制御（アクションボタン + フィールド非表示）     │
│  → ユーザーが操作できる導線を制限                          │
├─────────────────────────────────────────────────────────┤
│  Layer 2: データバリデーション（Editable_If）              │
│  → フォーム経由での不正入力を拒否                          │
├─────────────────────────────────────────────────────────┤
│  Layer 3: オートメーションBot（セーフティネット）           │
│  → 万が一すり抜けた場合の自動補正                          │
└─────────────────────────────────────────────────────────┘
```

### 6.2 Layer 1: UI制御

**算定フラグのフォーム直接編集を禁止**

医師算定・衛生士算定カラムを `Editable_If = FALSE` に設定し、
フォーム上でのトグル操作を不可にする。
値の変更はアクションボタン経由のみ。

※ アクションの「Set column values」は Editable_If = FALSE でも値を書き換え可能

**アクションボタンによる算定操作**

- ON/OFFの両方をアクションで提供（5.3 アクション定義を参照）
- アクションの表示条件（Only if）で上限チェックを行い、条件を満たさない場合はボタン自体が非表示になる
- キャンセル時に算定フラグを自動リセット（算定回数の整合性を維持）

### 6.3 Layer 2: データバリデーション

**算定カウントのキャンセル除外**

当月医師算定回数・当月衛生士算定回数の計算式に `[ステータス] <> "キャンセル"` を含め、
キャンセル済みスケジュールの算定を回数カウントから除外する（4.1 参照）。

**算定ステータスの可視化**

診療スケジュールに以下の仮想列を追加し、Detail Viewで算定状態を明示する。

```
【医師算定ステータス表示】
IF(
  [医師算定] = TRUE,
  "✓ 算定済み",
  IF(
    [患者ID].[医師算定残り] > 0,
    "算定可（残" & [患者ID].[医師算定残り] & "回）",
    "✗ 上限到達"
  )
)

【衛生士算定ステータス表示】
IF(
  [衛生士算定] = TRUE,
  "✓ 算定済み",
  IF(
    [患者ID].[衛生士算定残り] = 0,
    "✗ 上限到達",
    IF(
      AND([衛生士滞在時間] > 0, [衛生士滞在時間] < 20),
      "✗ 20分未満（" & [衛生士滞在時間] & "分）",
      "算定可（残" & [患者ID].[衛生士算定残り] & "回）"
    )
  )
)
```

### 6.4 Layer 3: オートメーションBot（セーフティネット）

スプレッドシート直接編集や同時操作による競合を防ぐ最終防御。

**患者マスタに追加する仮想列：**

```
【当月医師算定超過】
[当月医師算定回数] > 2

【当月衛生士算定超過】
[当月衛生士算定回数] > 4
```

**Bot: 医師算定超過自動修正**

| 項目 | 設定 |
|------|------|
| Event | 診療スケジュール Updates |
| Condition | `AND([医師算定] = TRUE, [患者ID].[当月医師算定超過] = TRUE)` |
| Step | Set 医師算定 = FALSE |

**Bot: 衛生士算定超過自動修正**

| 項目 | 設定 |
|------|------|
| Event | 診療スケジュール Updates |
| Condition | `AND([衛生士算定] = TRUE, [患者ID].[当月衛生士算定超過] = TRUE)` |
| Step | Set 衛生士算定 = FALSE |

### 6.5 Format Rules（視覚的フィードバック）

| 条件 | 色 | 対象 |
|------|-----|------|
| `[医師算定] = TRUE` | 緑背景 | 医師算定ステータス表示 |
| `[患者ID].[医師算定残り] = 0 AND [医師算定] = FALSE` | 赤文字 | 医師算定ステータス表示 |
| `[衛生士算定] = TRUE` | 緑背景 | 衛生士算定ステータス表示 |
| `[患者ID].[衛生士算定残り] = 0 AND [衛生士算定] = FALSE` | 赤文字 | 衛生士算定ステータス表示 |
| `[20分警告] <> ""` | 黄背景 | 衛生士滞在時間 |

### 6.6 GASの位置づけ

算定制限にGASは不要。AppSheetネイティブ機能のみで完結する。
既存のスケルトンコード（`gas-integration/Code.gs`）は将来のレセプト連携用に温存する。

| 機能 | AppSheet | GAS |
|------|----------|-----|
| 算定上限チェック | ✅ Virtual Column + Action条件 | 不要 |
| リアルタイムバリデーション | ✅ Editable_If + Only if | 不要 |
| 同時操作の競合防止 | ✅ Automation Bot | 不要 |
| 月次レセプト出力（将来） | 困難 | 必要になる可能性 |

## 8. 今後の拡張検討

### 8.1 定期スケジュール自動生成

患者マスタの「訪問頻度」「曜日」から、月間スケジュールを一括生成する機能

```
【例】
患者A：訪問頻度=月2、曜日=水
→ 当月の第2水曜、第4水曜に自動でスケジュール作成
```

### 8.2 移動時間の自動計算

施設マスタの住所から、施設間の移動時間を概算

```
【例】
施設A → 施設B：車で30分
→ 施設Aの終了時間 + 30分 = 施設Bの開始可能時間
```

### 8.3 レセプト出力連携
