# 基本スケジュール自動生成 実装ガイド（検証済み v2）

## 概要

患者マスタに「基本スケジュール」（週数・曜日・時間）と「ステータス」を追加し、
毎月ボタン1つで診療スケジュールを自動生成する機能を実装する。

### 要件

1. **基本スケジュール**: 週数1・週数2（1〜4）、曜日、時間を患者ごとに設定
2. **ステータス**: 治療（長期）/治療（単発）/ケア/終了。終了の患者はスケジュール生成対象外
3. **月次一括生成**: ボタン押下で対象月のスケジュールを自動作成
4. **自動生成後の編集**: 自動生成されたスケジュールは手動で修正可能
5. **手動追加**: 従来通りの手動スケジュール追加も継続

### 技術検証結果

AppSheet公式ドキュメントに基づいて全機能の実現可能性を検証済み。
以下の4点について初版設計から修正を反映:

| 検証項目 | 結果 | 修正内容 |
|---------|------|----------|
| 週数のデータ型 | EnumListは最大2選択に対して過剰 | Enum × 2カラム（週数1・週数2）に変更。IN()+SPLIT()バグも根本解消 |
| 日付計算の仮想列 | 4仮想列（第1~4週）は冗長、DATE()3引数は使えない | 2仮想列（_訪問日1・_訪問日2）に変更。Date算術+NUMBER()で週数から直接計算 |
| _生成対象月のMAX() | 日付MAX≠最新レコード | 生成日時ベースの取得に変更 |
| Bot構成パターン | "For each row"は厳密には別構成 | Action「Execute on set of rows」パターンに変更 |

### 1.4 AppSheet カラム設定詳細

#### ステータス
```
Type: Enum
Values: 治療（長期）, 治療（単発）, ケア, 終了
Default Value: "治療（長期）"
Required: TRUE
Description: 患者の診療状態。終了にすると新規スケジュール生成対象外
```

#### 週数1
```
Type: Enum
Values: 1, 2, 3, 4
Required: FALSE
Description: 1回目の訪問週（例: 1を選択 → 第1週に訪問）
```

#### 週数2
```
Type: Enum
Values: 1, 2, 3, 4
Required: FALSE
Show_If: [訪問頻度] = "月2"
Description: 2回目の訪問週（例: 3を選択 → 第3週に訪問）。訪問頻度が月2の場合のみ表示
```

**バリデーション（週数2に設定）:**
```
OR(
  ISBLANK([_THIS]),
  [_THIS] <> [週数1]
)
```
メッセージ: "週数1と同じ値は選択できません"

> **設計判断**: 旧設計では EnumList（複数選択）を使用していたが、
> 週数の選択は最大2つに固定されるため、Enum × 2カラムに変更。
> これにより (1) 数式での個別値参照が簡潔になり、
> (2) Bot実行時の IN()+SPLIT() サーバーサイドバグを回避でき、
> (3) Show_If による訪問頻度連動の表示制御が容易になった。

#### 曜日
```

Values: 月, 火, 水, 木, 金, 土
Required: FALSE
Description: 基本スケジュールの訪問曜日
```

#### 時間
```
Type: Time
Required: FALSE
Description: 基本スケジュールの訪問開始時間
```

月次スケジュール生成のトリガーとなるヘルパーテーブル。

### 2.1 Googleスプレッドシートに新規シート追加

シート名: `スケジュール生成ログ`

| カラム名 | データ型 | Key | 設定 |
|---------|---------|-----|------|
| 生成ID | Text | ✓ | Initial: `CONCATENATE("GEN-", TEXT(NOW(), "YYYYMMDDHHMMSS"))` |
| 対象年月 | Date | | Required / Description: "生成したい月の1日を選択（例: 2026/03/01）" |
| 生成日時 | DateTime | | Initial: `NOW()` / Editable: FALSE |
| 備考 | Text | | |

### 2.2 バリデーションルール（重複生成防止）

対象年月カラムに設定:

```
ISBLANK(
  SELECT(
    スケジュール生成ログ[生成ID],
    AND(
      MONTH([対象年月]) = MONTH([_THISROW].[対象年月]),
      YEAR([対象年月]) = YEAR([_THISROW].[対象年月])
    )
  )
)
```

> バリデーションメッセージ: "この月のスケジュールは既に生成済みです。再生成する場合は、既存の生成ログを削除してください。"

## 3. 患者マスタ 新規仮想列

### 3.1 _生成対象月（内部用・非表示）

スケジュール生成ログの **最新レコード** から対象年月を取得する。

> **v2修正**: 初版では `MAX(SELECT(対象年月))` を使用していたが、
> これは「最新レコード」ではなく「最大日付値」を返すため誤り。
> 例: 4月分を生成済み → 3月分を追加生成しようとすると4月の日付が返る。
> 修正版は `生成日時` が最新のレコードの `対象年月` を取得する。

```
EOMONTH(
  ANY(
    SELECT(
      スケジュール生成ログ[対象年月],
      [生成日時] = MAX(
        SELECT(スケジュール生成ログ[生成日時], TRUE)
      )
    )
  ),
  -1
) + 1
```

> Show_If: FALSE（ユーザーには非表示）
>
> **EOMONTH による1日正規化**: `EOMONTH([date], -1)` は前月末日を返す。
> +1 することで必ず対象月の1日になる。対象年月に1日以外の日付が入った場合でも安全。
> 訪問日計算（`[_生成対象月] + 日数`）の前提条件を確実に保証する。
>
> 動作確認:
> - GEN-1: 対象年月=3/1, 生成日時=2/25 10:00
> - GEN-2: 対象年月=4/1, 生成日時=3/25 10:00
> - → _生成対象月 = 4/1 ✓（生成日時が最新のGEN-2の対象年月）
> - GEN-3: 対象年月=3/1（再生成）, 生成日時=3/26 09:00
> - → _生成対象月 = 3/1 ✓（生成日時が最新のGEN-3の対象年月）
> - GEN-4: 対象年月=4/15（誤入力）, 生成日時=3/27 09:00
> - → EOMONTH(4/15, -1) + 1 = 3/31 + 1 = 4/1 ✓（1日に正規化）

### 3.2 訪問日計算仮想列

患者の基本スケジュール（週数1・週数2・曜日）から、対象月における具体的な訪問日を算出する仮想列。2つ作成する。

**計算ロジック:**

```
対象月の1日の曜日番号 = WEEKDAY([_生成対象月])
  ※ _生成対象月は常に対象月の1日
  ※ WEEKDAY: 1=日, 2=月, 3=火, 4=水, 5=木, 6=金, 7=土

目標曜日番号 = SWITCH(曜日, "日",1, "月",2, ..., "土",7, デフォルト値)
  ※ AppSheetのSWITCH()はデフォルト値が必須

オフセット = MOD(目標曜日番号 - 第1日曜日番号 + 7, 7)

訪問日 = [_生成対象月] + オフセット + (N - 1) × 7
  ※ AppSheetではDate型 + 数値で日数加算が可能
  ※ NにはNUMBER([週数N])を使用（Enum型はTextのため変換必要）
```

> **安全性**: 第4週の最大オフセットは offset(最大6) + 21 = 27日加算 → 28日目。
> 全ての月は28日以上あるため、週1〜4でオーバーフローすることはない。
>
> **AppSheet固有の制約（公式ドキュメント確認済み）**:
> - `DATE()` は**1引数のみ**（テキスト→Date変換）。`DATE(YEAR, MONTH, DAY)` の3引数形式は使えない
> - `SWITCH()` は**デフォルト値が必須**。省略するとエラー
> - `TEXT(数値, "00")` のゼロパディングは**不可**（2引数形式はDate/Time型のみ対応）
> - **Date型 + 数値で日数加算が可能**。`[_生成対象月]`（=対象月1日）に日数を足すことで、DATE()やTEXT()を使わずにシンプルに日付を構築できる
> - Enum型は内部的にTextのため、算術演算には `NUMBER()` で変換が必要

#### _訪問日1

週数1の値に基づいて、1回目の訪問日を算出する。

```
IF(
  AND(
    ISNOTBLANK([_生成対象月]),
    ISNOTBLANK([週数1]),
    ISNOTBLANK([曜日]),
    ISNOTBLANK([時間])
  ),
  [_生成対象月]
    + MOD(
        SWITCH([曜日], "日",1, "月",2, "火",3, "水",4, "木",5, "金",6, "土",7, 0)
        - WEEKDAY([_生成対象月])
        + 7,
        7
      )
    + (NUMBER([週数1]) - 1) * 7,
  ""
)
```

> Show_If: FALSE（ユーザーには非表示）
>
> **数式の読み方**:
> - `[_生成対象月]`（=対象月の1日）をベースに日数を加算
> - `MOD(...)` で対象月1日から最初の目標曜日までの日数差（0〜6）を算出
> - `(NUMBER([週数1]) - 1) * 7` で指定週まで7日ずつ進む
> - SWITCH末尾の `0` はAppSheet必須のデフォルト値（曜日が設定済みなら到達しない）

#### _訪問日2

週数2の値に基づいて、2回目の訪問日を算出する。
`[訪問頻度] = "月2"` ガードにより、Show_Ifで週数2が非表示のまま古い値が残留している場合でも安全に動作する。

```
IF(
  AND(
    ISNOTBLANK([_生成対象月]),
    ISNOTBLANK([週数2]),
    [訪問頻度] = "月2",
    ISNOTBLANK([曜日]),
    ISNOTBLANK([時間])
  ),
  [_生成対象月]
    + MOD(
        SWITCH([曜日], "日",1, "月",2, "火",3, "水",4, "木",5, "金",6, "土",7, 0)
        - WEEKDAY([_生成対象月])
        + 7,
        7
      )
    + (NUMBER([週数2]) - 1) * 7,
  ""
)
```

> Show_If: FALSE（ユーザーには非表示）
>
> **Show_If残留データ対策**: AppSheetのShow_Ifはフィールドを非表示にするだけで、
> 値のクリアは行わない（UI制御のみ）。訪問頻度を「月2→月1」に変更した場合、
> 週数2の値が残ったままになる可能性がある。`[訪問頻度] = "月2"` ガードにより、
> 訪問頻度が「月1」の場合は週数2に値が残っていても _訪問日2 は空になるため、
> 不要なスケジュールが生成されることはない。

> **検証例（2026年3月: _生成対象月=3/1 日曜日 WEEKDAY=1）:**
>
> | 患者例 | 週数1 | 週数2 | 曜日 | _訪問日1 | _訪問日2 |
> |--------|-------|-------|------|----------|----------|
> | 月2・月曜・第1,3週 | 1 | 3 | 月 | 3/2 ✓ | 3/16 ✓ |
> | 月2・水曜・第2,4週 | 2 | 4 | 水 | 3/11 ✓ | 3/25 ✓ |
> | 月1・金曜・第2週 | 2 | - | 金 | 3/13 ✓ | (空) ✓ |
>
> 計算過程（月曜・第1週）: 3/1 + MOD(2-1+7, 7) + (1-1)*7 = 3/1 + 1 + 0 = 3/2 ✓
> 計算過程（月曜・第3週）: 3/1 + MOD(2-1+7, 7) + (3-1)*7 = 3/1 + 1 + 14 = 3/16 ✓
>
> **検証例（2026年4月: _生成対象月=4/1 水曜日 WEEKDAY=4）:**
>
> | 患者例 | 週数1 | 週数2 | 曜日 | _訪問日1 | _訪問日2 |
> |--------|-------|-------|------|----------|----------|
> | 月2・月曜・第1,3週 | 1 | 3 | 月 | 4/6 ✓ | 4/20 ✓ |
> | 月2・金曜・第2,4週 | 2 | 4 | 金 | 4/10 ✓ | 4/24 ✓ |
> | 月1・木曜・第2週 | 2 | - | 木 | 4/9 ✓ | (空) ✓ |
>
> 計算過程（月曜・第1週）: 4/1 + MOD(2-4+7, 7) + (1-1)*7 = 4/1 + 5 + 0 = 4/6 ✓
> 計算過程（金曜・第4週）: 4/1 + MOD(6-4+7, 7) + (4-1)*7 = 4/1 + 2 + 21 = 4/24 ✓

### 3.3 基本スケジュール表示（ユーザー向け）

```
IF(
  AND(ISNOTBLANK([週数1]), ISNOTBLANK([曜日]), ISNOTBLANK([時間])),
  "第" & [週数1] & IF(ISNOTBLANK([週数2]), "・" & [週数2], "") & "週 " & [曜日] & "曜 " & TEXT([時間], "HH:MM"),
  ""
)
```

> 表示例: "第1・3週 月曜 09:00"（月2の場合）、"第2週 木曜 09:00"（月1の場合）

## 4. アクション＋Automation Bot: 月次スケジュール自動生成

### 4.1 全体構成

> **v2修正**: Bot内で直接「For each row + Branch」を使う構成から、
> Action「Execute an action on a set of rows」を使う構成に変更。
> これはAppSheetの標準パターンであり、より確実に動作する。

```
┌─────────────────────────────────────────────────────────────┐
│ Bot: 月次スケジュール自動生成                                │
│                                                             │
│ Event: スケジュール生成ログ - Adds only                      │
│                                                             │
│ Process:                                                    │
│   Step: Run a data action → 「月次一括生成」                 │
└──────────────────────┬──────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────┐
│ Action: 月次一括生成                                         │
│ Type: Execute an action on a set of rows                    │
│ For a record of: スケジュール生成ログ                         │
│ Referenced Table: 患者マスタ                                 │
│ Referenced Rows: SELECT(患者マスタ[ID], AND(                 │
│   [ステータス]<>"終了", ISNOTBLANK([週数1]),                  │
│   ISNOTBLANK([曜日]), ISNOTBLANK([時間])))                   │
│ Referenced Action: 「個別患者スケジュール生成」               │
└──────────────────────┬──────────────────────────────────────┘
                       │ 各患者に対して実行
                       ▼
┌─────────────────────────────────────────────────────────────┐
│ Action: 個別患者スケジュール生成                              │
│ Type: Grouped (Sequence of actions)                         │
│ For a record of: 患者マスタ                                  │
│                                                             │
│ Sub-actions:                                                │
│   1. 訪問日1スケジュール追加 (Only if: _訪問日1が有効)        │
│   2. 訪問日2スケジュール追加 (Only if: _訪問日2が有効)        │
└─────────────────────────────────────────────────────────────┘
                       │ 各サブアクション
                       ▼
┌─────────────────────────────────────────────────────────────┐
│ Action: 訪問日Nスケジュール追加                              │
│ Type: Data: Add a new row to another table                  │
│ For a record of: 患者マスタ                                  │
│ Target table: 診療スケジュール                                │
│                                                             │
│ Only if:                                                    │
│   ISNOTBLANK([_訪問日N])                                     │
│   AND 重複チェック                                           │
│                                                             │
│ Set columns:                                                │
│   訪問日 = [_訪問日N]  (Virtual Column)                       │
│   訪問開始時間 = [時間]                                       │
│   患者ID = [ID]                                              │
│   施設ID = [施設ID]                                           │
│   ステータス = "予定"                                         │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 Action 設定詳細

#### Action 1: 月次一括生成

```
Action name: 月次一括生成
For a record of: スケジュール生成ログ
Do this: Execute an action on a set of rows

Referenced Table: 患者マスタ
Referenced Rows:
  SELECT(
    患者マスタ[ID],
    AND(
      [ステータス] <> "終了",
      ISNOTBLANK([週数1]),
      ISNOTBLANK([曜日]),
      ISNOTBLANK([時間])
    )
  )
Referenced Action: 個別患者スケジュール生成

Prominence: Do not display
```

> このアクションはBot専用。ユーザーには非表示。

#### Action 2: 個別患者スケジュール生成

```
Action name: 個別患者スケジュール生成
For a record of: 患者マスタ
Do this: Grouped: execute a sequence of actions

Actions (in order):
  1. 訪問日1スケジュール追加
  2. 訪問日2スケジュール追加

Prominence: Do not display
```

> このアクションもBot専用。ユーザーには非表示。

#### Action 3: 訪問日1スケジュール追加

```
Action name: 訪問日1スケジュール追加
For a record of: 患者マスタ
Do this: Data: add a new row to another table using values from this row

Table to add row to: 診療スケジュール

Set these columns:
  スケジュールID: UNIQUEID()

  訪問日: [_THISROW].[_訪問日1]
  訪問開始時間: [_THISROW].[時間]
  患者ID: [_THISROW].[ID]
  施設ID: [_THISROW].[施設ID]
  ステータス: "予定"
  備考: "自動生成"
  作成日時: NOW()

Only if this condition is true:
  AND(
    ISNOTBLANK([_THISROW].[_訪問日1]),
    COUNT(
      SELECT(
        診療スケジュール[スケジュールID],
        AND(
          [患者ID] = [_THISROW].[ID],
          [訪問日] = [_THISROW].[_訪問日1],
          [ステータス] <> "キャンセル"
        )
      )
    ) = 0
  )

Prominence: Do not display
```

> **条件判定のシンプル化:**
> 旧設計では `OR([週数1] = N, [週数2] = N)` で4つのアクションそれぞれが
> 週番号をマッチングしていたが、仮想列 _訪問日1 が週数1の値から直接日付を計算するため、
> `ISNOTBLANK([_訪問日1])` だけで十分。週数1が未設定なら _訪問日1 は空になり、
> アクションは自動的にスキップされる。
>
> **重複防止:**
> `COUNT(SELECT(...)) = 0` で同一患者・同一日付のスケジュールが
> 既に存在しないことを確認。2回生成ボタンを押しても重複しない。

#### Action 4: 訪問日2スケジュール追加

訪問日1と同じ構成。差分のみ:

```
Action name: 訪問日2スケジュール追加

Set these columns:
  スケジュールID: UNIQUEID()
  訪問日: [_THISROW].[_訪問日2]
  （他は訪問日1と同じ）

Only if:
  AND(
    ISNOTBLANK([_THISROW].[_訪問日2]),
    COUNT(SELECT(診療スケジュール[スケジュールID], AND([患者ID]=[_THISROW].[ID], [訪問日]=[_THISROW].[_訪問日2], [ステータス]<>"キャンセル"))) = 0
  )
```

> **月1患者の安全性**: _訪問日2 の仮想列に `[訪問頻度] = "月2"` ガードがあるため、
> 月1患者では _訪問日2 は常に空。ISNOTBLANK条件によりこのアクションは自動スキップされる。

### 4.3 Bot 設定

```
Bot name: 月次スケジュール自動生成

  Event name: スケジュール生成トリガー
```

## 5. ステータス制御（終了患者の除外）

### 5.1 診療スケジュール フォームの患者選択制限

患者IDカラムの Valid_If を変更:

```
変更前: （制限なし）
変更後: SELECT(患者マスタ[ID], [ステータス] <> "終了")
```

> これにより、手動でスケジュールを追加する際も「終了」の患者は選択肢に表示されない。

### 5.2 患者一覧ビュー のフィルター

既存の「患者一覧」ビューにフィルター条件を追加:

```
Filter: [ステータス] <> "終了"
```

> 終了患者も含めて表示したい場合は、別途「全患者一覧」ビューを作成するか、
> Slice を使ってフィルター切り替えを可能にする。

### 5.3 Format Rule: 終了患者の視覚表示

```
Rule name: 終了患者
For this data: 患者マスタ
Condition: [ステータス] = "終了"
Format: Text color = グレー（#9E9E9E）, Strikethrough
Apply to: 氏名
```

## 7. 運用フロー

### 7.1 初期設定（1回だけ）

```
1. 全患者のステータスを確認（デフォルト: 治療（長期））
2. 患者の状態に応じて「治療（単発）」「ケア」に変更
3. 診療終了患者は「終了」に変更
3. 各患者の基本スケジュールを設定:
   - 週数1: 例) 1（第1週）
   - 週数2: 例) 3（第3週）※月2の場合のみ
   - 曜日: 例) 月
   - 時間: 例) 09:00
```

### 7.2 月次スケジュール生成（毎月）

```
1. ナビゲーション → 「スケジュール生成」を選択
2. 対象年月に来月の1日を入力（例: 2026/04/01）
3. 保存ボタンを押す
4. Bot が自動実行:
   - 終了以外の患者 × 設定された週数分のスケジュールが自動作成
   - 既に存在するスケジュールはスキップ（重複防止）
   - 処理時間: 45患者で数十秒程度
5. 診療スケジュール一覧で確認（Syncボタンで最新化）
6. 必要に応じて手動で調整:
   - 時間変更
   - 担当医師・衛生士の割り当て
   - 診療内容の記入
   - 不要なスケジュールのキャンセル
   - 手動でのスケジュール追加
```

### 7.3 患者の終了処理

```
1. 患者一覧 → 対象患者を選択
2. ステータスを「終了」に変更
3. 効果:
   - 以降のスケジュール自動生成から除外
   - 手動スケジュール追加時の患者選択肢から除外
   - 既存のスケジュール（過去分）は変更されない
```

## 8. AppSheetでの実現可能性まとめ

### 検証済み（公式ドキュメント確認済み）

| 要件 | 実現方法 | 確実性 | 検証根拠 |
|------|----------|--------|----------|
| 基本スケジュール設定 | Enum × 2 + Enum + Time カラム | ✅ | AppSheet標準機能 |
| ステータス管理 | Enum + Valid_If フィルター | ✅ | AppSheet標準機能 |
| 月次一括生成 | Bot → Execute on set of rows → Add row | ✅ | 公式ドキュメント確認済み |
| 日付計算（週数から訪問日） | Date算術（[_生成対象月] + 日数） + WEEKDAY/MOD/NUMBER | ✅ | 数学的に検算済み（6パターン）。Date+数値の日数加算は公式確認済み |
| 訪問日の有効判定 | ISNOTBLANK([_訪問日N]) | ✅ | 仮想列が空=スキップ。週数判定を仮想列に集約 |
| Enum型の数値変換 | NUMBER([週数N]) | ✅ | AppSheet標準関数。Enum内部はTextのため算術演算に必要 |
| SWITCH()デフォルト値 | 末尾に0を追加 | ✅ | AppSheetではデフォルト値が必須（公式仕様） |
| DATE()1引数制約の回避 | Date算術（[_生成対象月]+日数） | ✅ | DATE(Y,M,D)は使えないが、Date+数値で日数加算可能（公式確認済み） |
| Show_If残留データ対策 | _訪問日2に[訪問頻度]="月2"ガード | ✅ | Show_Ifは値クリアしないため、仮想列側で防御 |
| Virtual Columnのbot内利用 | サーバーサイドで再計算 | ✅ | 公式ドキュメント確認済み |
| 重複防止 | COUNT(SELECT()) = 0 | ✅ | 公式ドキュメント確認済み |
| 自動生成後の編集 | 通常の診療スケジュール編集 | ✅ | 既存機能そのまま |
| 手動追加の継続 | 既存フォーム/ビュー | ✅ | 既存機能そのまま |

### 注意点・制約

1. **Bot実行時間**: 45患者 × 最大2アクション = 最大90評価。数十秒で完了する見込み。
2. **1回の生成レコード数**: 45患者 × 2週 = 最大90レコード。AppSheet処理能力内。
3. **スケジュールIDの一意性**: UNIQUEID()で生成するため衝突しない。
4. **週数カラム**: Enum × 2カラム（週数1・週数2）のため、旧EnumListのデリミタ問題は発生しない。
5. **Enum型の算術演算**: 週数1・週数2はEnum型（内部Text）のため、NUMBER()で変換が必要。変換せずに算術演算するとエラーになる。

### 残存リスク（低確率だが記録）

| リスク | 確率 | 影響 | 対策 |
|--------|------|------|------|
| _生成対象月の仮想列がBot実行前に更新されない | 極低 | 誤った月の日付で生成 | 公式ドキュメントでは「再計算される」と記載。問題発生時はGASに切り替え |
| 週数1と週数2の不整合 | 極低 | 同じ週が2回生成される | バリデーション（週数1 ≠ 週数2）で防止。万一通過してもCOUNT重複チェックで2行目はスキップ |
| Show_Ifで非表示の週数2に値が残留 | 低 | 月1患者に2回目のスケジュール生成 | _訪問日2に[訪問頻度]="月2"ガードを設定。残留値があっても訪問日は計算されない |
